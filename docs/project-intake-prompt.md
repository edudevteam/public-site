# Project intake prompt

Describe this project for our team's portfolio page. Read the repository (README,
dependency files, source code and config) and base everything on what the code actually
does. Don't make up features, numbers, URLs or audiences. If you aren't sure about
something, mark it "TODO" and list it at the end.

Include:

1. **Title**: the project's name.
2. **Tagline**: one sentence, under 25 words, saying what you can do with it.
3. **What it does**: 2–3 short paragraphs explaining what the project is, how someone uses
   it, where it runs, and what they need to use it (install, account, API key, hardware).
4. **Key features**: 4–6 bullet points, each a short sentence starting with a verb.
5. **Who it's for**: 2–3 types of people and why they'd use it.
6. **How it works**: one short paragraph for a non-expert explaining how the main part
   works.
7. **Stack and tools**: the languages, frameworks, libraries, APIs and services used, with
   a few words on what each one does in this project.
8. **Tags**: 8–12 lowercase keywords people might search for.
9. **Needs checking**: anything you guessed, couldn't confirm, or that looked
   contradictory.

Write plainly, in the second person ("you"), with short sentences. Say what the project
does, not how great it is. Skip words like "seamless", "powerful", "cutting-edge",
"robust" or "intuitive", and explain any jargon.

> Output this in the prompt in a Markdown code block so it can be copied.
